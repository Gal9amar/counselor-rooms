# תכנית: ניווט "אחורה" בדפדפן בין מסכים (לביצוע בעתיד)

**סטטוס:** לא בוצע. נשמר לפי בקשת הבעלים. בדיקות לפי הכלל הקבוע: בדיקות חובה בלבד.

## הבעיה
מסכים רבים באפליקציה הם שלבים או חלונות בתוך אותו עמוד, בלי כתובת ובלי רשומה בהיסטוריית הדפדפן. לחיצה על "אחורה" מדלגת על כל השלבים וחוזרת לאתר הקודם. הרצוי: "אחורה" חוזרת למסך הקודם באפליקציה.

## מסכים בהיקף
- `/new-booking` (`NewBookingPage.jsx`): בחירת סוג, אחר כך טופס ולוח, ובתפזורת גם בחירת שעות לתאריך.
- `/schedule` (`SchedulePage.jsx`): בחירת חדר, בחירת תאריך, בחירת שעה.
- דשבורד (`DashboardPage.jsx`): חלון החדר (`RoomModal`) וחלון הוספת שיבוץ (`AddBookingModal`), וגם תצוגות (כרטיסים, ציר זמן, שבועי) אם הן מוחלפות בלי כתובת.
- חלון התחברות המנהל (`AdminLoginModal`), ולשוניות פאנל הניהול (`AdminPage`, כולל `?tab=`).

## גישה מוצעת
1. Hook משותף `client/src/hooks/useBackStep.js`: בכל מעבר קדימה `history.pushState({ app: true, step }, '')` (או `navigate` של React Router עם `state` / `?step=`), ובאירוע `popstate` מחזיר את השלב הקודם במקום לצאת. חלון פתוח נסגר ב"אחורה".
2. שלבי אשף שנשמרים ב-`location.state`, כך שרענון עמוד נטען תקין. אם אין state חוזרים לשלב הראשון.
3. הנתונים שהוזנו בטופס נשמרים בזיכרון הרכיב ולא מתאפסים בחזרה לשלב.
4. מעבר קדימה ושלבים אחוריים לא יוצרים רשומות כפולות (לא `push` כשהשלב לא השתנה). מעבר "חזרה" מתוך הממשק (כפתור "חזרה") קורא `history.back()` ולא `push`.
5. אין מלכודת: מהשלב הראשון "אחורה" יוצאת מהאתר כרגיל.

## מקרי קצה לבדיקה
- פתיחה ישירה של כתובת באמצע זרימה, רענון באמצע אשף, מעבר קדימה אחרי חזרה.
- חלון פתוח + "אחורה" = נסגר בלי לעזוב את העמוד. שני חלונות מקוננים נסגרים אחד אחד.
- `?tab=` בפאנל הניהול לא יוצר רשומות מיותרות בהחלפת לשונית (`replace` ולא `push`).
- כפתור "אחורה" בחלון הפנימי של האפליקציה ו"אחורה" בדפדפן מתנהגים אותו דבר.

## בדיקות חובה בלבד (בסיום הביצוע)
1. `npm run build` בלקוח עובר.
2. בדיקת דפדפן קצרה (Playwright, API מדומה): ב-`/new-booking` ו-`/schedule` מעבר של 2 שלבים ואז `history.back()` חוזר לשלב הקודם ולא ל-`about:blank` או לאתר הקודם; חלון חדר נסגר ב"אחורה"; רענון לא שובר.
3. בלי בדיקות אבטחה/SQL/QA מלאות, כי אין שינוי בנתונים או בהרשאות.
